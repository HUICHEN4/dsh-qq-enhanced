# 上下文压缩：谁在压、怎么配

> 一句话结论：**桥接自己不负责压缩。** 真正把长对话折叠成摘要的，是 DSH 那边的上下文管理插件；桥接自带的 `compact` 阈值很高，正常聊到不了，别指望它。想让 QQ 侧像作者的部署一样省钱、不爆上下文，需要你在 **DSH 里** 配一次。

## 一、一共有三层，别搞混

| 层 | 在哪 | 实际作用 | 要不要动 |
| --- | --- | --- | --- |
| 桥接自带的 compact | `config.json` → `socialV2.compact` | 超过 `thresholdTokens` 才折叠一次，默认 450000 | **基本不用动**，保持默认即可 |
| DSH 上下文压缩插件 | DSH 侧（本仓库之外） | 每轮上下文涨到阈值就折叠成摘要块，这才是日常真正在跑的那层 | **要配**，见第三节 |
| 手动换会话 | 控制台「会话 → 清除上下文」或 `POST /api/session/reset` | 彻底换一个新会话，旧会话归档 | 需要时手动做，见 [LONG_RUNNING.md](LONG_RUNNING.md) |

## 二、桥接自带的 compact（多半用不上）

`socia2V2.compact` 默认：

```json
"compact": {
  "enabled": true,
  "thresholdTokens": 450000,
  "cooldownMinutes": 120,
  "idleDelayMs": 20000
}
```

- 触发条件是单会话上下文超过 **450000 token**。一个活跃的 QQ 群会话通常到 100K～150K 就已经该手动换会话了，所以这个值实际上很少被触发。
- 它和 DSH 侧的压缩**功能重叠**。如果你把阈值调得很低（比如 50000），会出现「桥接压一次、DSH 再压一次」的双重折叠，摘要里套摘要，反而更费 token、更容易失忆。
- 结论：**保持默认，或者干脆 `enabled: false`**，把压缩交给下一层。

## 三、DSH 侧的上下文压缩（真正在跑的那层）

作者部署里用的是 `billion-context` 这类上下文管理插件。不同 DSH 版本、不同插件名字/路径可能不一样，配置项通常长这样：

- 配置文件：`C:\Users\<你的用户名>\.config\billion-context\billion-context.json`（Linux/macOS 在 `~/.config/...`）
- 关键字段：

| 字段 | 作者的取值 | 含义 |
| --- | --- | --- |
| `nudgeGrowthTokens` | `40000` | 上下文每**净增长** 4 万 token 触发一次折叠。调小 = 折得勤、单轮便宜但摘要块多；调大 = 折得少、单轮更贵 |
| `modelContextLimit` | `350000` | 认为模型能吃的上下文上限 |
| `maxContextLimit` | `"60%"` | 实际允许用到的比例（这里是 350000 的 60%，约 210K） |
| `maxSummaryLength` | `4000` | 单个摘要块的字数上限 |

**建议起点**：`nudgeGrowthTokens` 用 40000。这是个折中值——太低（比如 10000）会让摘要块迅速堆满前缀，等于用摘要换原文；太高（比如 100000）单轮上下文长期偏大，每步都在为长前缀付费。

改完要重启 DSH 才生效。

## 四、为什么你会看到「80K ↔ 120K」来回跳

折叠不会在阈值处立刻发生，而是等上下文**再涨一个 `nudgeGrowthTokens`** 才触发一次。所以曲线通常是锯齿形：慢慢涨到 120K，被折回 80K 左右，再涨。看到这个形状说明压缩在工作，不是 bug。

摘要块会一直留在前缀里累积——这就是为什么会话跑久了「地板」会越来越高，最后还是要手动换会话。

## 五、怎么判断到底压没压

- 会话越聊越短、前面细节记不清 → 在压，而且压得比较狠
- 控制台看板里单轮 cost 缓慢上升但没爆 → 正常
- 一轮 cost 突然翻倍 → 要么折叠触发了（前缀变大），要么步数变多了（多气泡、看图、等待）；后者更常见

## 六、没有这类插件怎么办

如果目标机器的 DSH 没有装上下文管理插件，行为由 DSH 自带机制决定，那就不用管这一页——只要记住两件事：

1. 别把桥接的 `socialV2.compact.thresholdTokens` 调低；
2. 会话长了就按 [LONG_RUNNING.md](LONG_RUNNING.md) 手动换会话，换前先交接记忆。

## 七、不建议做的事

- ❌ 把桥接 compact 阈值调低「省 token」——会导致双重压缩
- ❌ 频繁 reset 换会话——每次都要重新冷启动（首次 miss 约 5 万 token），且会丢该会话记忆
- ❌ 为了省 token 关掉卡片/工具——省下的钱远小于一次前缀失效的代价
