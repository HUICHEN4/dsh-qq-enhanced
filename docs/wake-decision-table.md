# 唤醒决策表（现状快照，2026-11-06 13:10）

> 目的：把「一条消息进来会发生什么」写成一张能一眼看完的表，用来核对代码。
> 本文只是**描述现状**，不代表我希望它长这样。冗余候选在最后一节。

## 0. 三种结局，三种价钱

| 结局 | 发生什么 | 大约花费 |
| --- | --- | --- |
| **只入库** | 记进未读 + 接续候选，不叫醒模型 | ¥0 |
| **接续批次** | 往同一个会话追加一条轻量提示（只给新消息） | ¥0.005~0.015 |
| **完整唤醒** | 重建一轮完整提示（角色卡/记忆/规则/快照/唤醒原因） | ¥0.03~0.10 |

核心原则：**接续在跑的时候，普通消息永远不该引发完整唤醒。**

## 1. 一条群消息进来：判定顺序（照 `evaluateWakeTriggerV2` 的实际代码顺序）

| # | 条件 | 结果 | 代码 |
| --- | --- | --- | --- |
| 0 | 私聊 | `private` → 完整唤醒 | `bridge.js:12181` |
| 1 | 该会话的有限窗口已过期 | 先清成深潜（`infinite=true`、撤 anyMessage），再继续往下判 | `12184-12194` |
| 2 | 消息里有真 `at` 段指向她 | `atMention` → 完整唤醒 | `12196-12201` |
| 3 | 消息是**引用她**（客户端自动带的 @ 不算） | `quoteSelf` → 接续在就立刻投一批；接续断了才完整唤醒 | `12202`, `13545` |
| 4 | `anyMessage` 开着且不在监控窗内 | `anyMessage` → 完整唤醒 | `12204` |
| 5 | 文字里出现她的昵称 | `nameMention` → 完整唤醒 | `12205-12210` |
| 6 | 命中关键词（短英文用词边界） | `keyword:xx` → 完整唤醒 | `12211-12223` |
| 7 | 像在提问/点她 | `question` → 完整唤醒 | `12224` |
| 8 | 发言人命中 `speakerIds` 白名单 | `speaker:xx` → 完整唤醒 | `12225-12231` |
| 9 | 当前在监控窗内 | **null**（只入库） | `12232` |
| 10 | 接续正在跑 | **null**（交给接续，见上一行第 3 条） | `12235` |
| 11 | 概率 > 0，且距上次唤醒未超过冷启动阈值，且掷骰命中 | `probability` → 完整唤醒 | `12236-12252` |
| 12 | 以上都不是 | **null**（只入库） | `12253` |

没命中则交给 `noteContinuationMessageV2`，按 12 秒（热聊）/60 秒（沉默）合批。

## 2. 计划唤醒之后的五道闸（`scheduleWakeV2` → `sendWakePromptV2`）

| # | 闸 | 触发时 |
| --- | --- | --- |
| 1 | 模式/暂停/会话不在允许范围 | 丢弃 |
| 2 | 合并窗口里已有待发唤醒 | 按优先级升级原因（`atMention 90 > question 80 > nameMention 70 > …`） |
| 3 | 会话繁忙（模型正在跑） | 暂存原因，最多 20 条 |
| 4 | 定时静默（09:00-12:00 / 14:00-18:00 工作日） | 不唤醒；真点名记 `silenceMissedDirect`，静默结束后补 |
| 5 | 限频（1/分钟、15/小时；窗口类另有 20/小时软名额） | **每 60 秒重试**直到有位置（按优先级插队） |

## 3. 非消息的触发源

| 触发源 | 频率/条件 | 结局 |
| --- | --- | --- |
| 回复检查 `replyCheck` | 发完话 30 秒后（她问了问题 ×1.5、连发 ≥3 条 ×1.3） | 有未读才唤醒；接续在跑就整个跳过 |
| 有限睡眠到期 | 到 `sleepUntil` | 监控窗 → 安静进深潜（不唤醒）；她自己设的睡眠 → `timeout` 唤醒 |
| 主动机会 `proactive` | 1~3 小时一次，空闲 15 分钟，概率 0.15，冷启动 ×0.2 | 完整唤醒（唯一「没人说话也会醒」的） |
| 启动补扫 @ | 启动后 8 秒，各群最后 15 条 | 命中 @ 才完整唤醒 |
| 首次接触 `bootstrap` | 每个会话一次 | 完整唤醒 |

## 4. 她自己调工具时

| 动作 | 效果 |
| --- | --- |
| 发消息 | 触发 `startContinuationV2`：进入/续期接续 |
| `qq_mark_read` | 标已读；接续在跑就保留接续，否则结束接续 |
| `qq_set_wake_config` | 改唤醒条件；**会结束接续**（所以提示词叫她别在话题继续时调） |
| 说「去睡了/晚安」 | `isSleepPhrase` 命中 → 结束接续 + 深潜 4 小时（硬触发仍能叫醒） |

## 6. 一句话总结

现在有 **三类触发源（消息 / 定时器 / 她自己）× 两层闸（判定 + 限频静默）× 两种投递（接续 / 完整）**，
组合出十几个分支——这就是「乱」的来源。钱已经省到位了，下一步只该减分支。
